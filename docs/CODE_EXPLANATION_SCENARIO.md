# 코드 설명 발표 시나리오

이 문서는 과제 평가자에게 코드를 설명할 때 그대로 따라갈 수 있는 대본입니다.
전체 설명은 약 7분, 실행 시연은 약 2분을 기준으로 합니다.

## 먼저 기억할 핵심 한 문장

> 사용자의 입력을 검증해 기능을 실행하고, `Quiz` 객체들의 상태와 점수 기록을
> JSON에 저장해 다음 실행에서도 이어지는 Python 콘솔 퀴즈 게임입니다.

설명할 때는 문법 이름만 나열하지 말고 항상 다음 순서로 말합니다.

```text
과제에서 요구한 것 → 사용한 Python 개념 → 실제 코드 → 그렇게 만든 이유
```

## 7분 코드 설명 대본

### 1. 프로젝트 소개: 약 30초

열어 둘 파일: `README.md`

말할 내용:

> 이 프로젝트는 Python 기초 문법을 주제로 한 터미널 퀴즈 게임입니다.
> 주제를 Python으로 정한 이유는 프로그램을 구현하면서 사용한 리스트,
> 딕셔너리, 조건문, 반복문, 함수를 퀴즈로 다시 복습할 수 있기 때문입니다.
> 필수 기능인 풀이, 추가, 목록, 최고 점수, JSON 저장을 구현했고, 다섯 가지
> 보너스 기능도 모두 추가했습니다.

주의할 숫자:

- 코드에 정의된 기본 퀴즈는 7개입니다.
- 현재 `state.json`에는 사용자가 직접 추가한 1개가 더 있어 8개입니다.
- `state.json`을 삭제하거나 복구하면 기본 7개로 다시 시작합니다.

### 2. 프로그램이 시작되는 과정: 약 40초

열어 둘 코드: `main.py:3-12`, `quiz_game.py:25-33`

말할 내용:

> `main.py`는 프로그램의 시작점입니다. `QuizGame()`으로 게임 객체를 만들고
> `run()`을 호출합니다. `if __name__ == "__main__"` 조건은 이 파일을 직접
> 실행했을 때만 `main()`이 호출되도록 합니다. `QuizGame`의 `__init__`에서는
> 기본 속성을 만든 뒤 `load_state()`를 호출합니다. 따라서 메뉴가 뜨기 전에
> 이전 퀴즈와 점수 기록이 먼저 복구됩니다.

여기서 설명할 Python 개념:

- `game`은 `QuizGame` 객체를 가리키는 변수입니다.
- `__init__`은 객체가 생성될 때 자동으로 실행됩니다.
- `self`는 현재 만들어진 게임 객체 자신입니다.
- `self.quizzes`는 객체가 가진 속성이고 `run()`은 객체가 수행하는 메서드입니다.

### 3. 두 클래스의 역할: 약 1분

열어 둘 코드: `quiz.py:4-60`, `quiz_game.py:20-33`

말할 내용:

> 과제에서 최소 두 개의 클래스를 요구합니다. 저는 단순히 개수를 맞춘 것이
> 아니라 역할을 기준으로 나눴습니다. `Quiz`는 문제 한 개의 질문, 선택지,
> 정답, 힌트를 가지고 출력과 정답 확인을 담당합니다. `QuizGame`은 여러
> `Quiz` 객체를 리스트로 관리하면서 메뉴, 플레이, 점수, 파일 저장을
> 담당합니다. 이렇게 나누면 문제 데이터의 규칙과 게임 진행 규칙을 각각
> 독립적으로 수정하고 테스트할 수 있습니다.

`Quiz.__init__`을 가리키며 이어서 말합니다.

> 문제는 비어 있지 않은 문자열인지, 선택지는 정확히 네 개인지, 정답은
> 1부터 4 사이의 정수인지 생성 시점에 검사합니다. 잘못된 객체가 게임
> 리스트나 JSON에 들어오기 전에 `ValueError`를 발생시키는 구조입니다.

자료형 연결:

- `question`, `hint`: `str`
- `answer`: `int`
- `choices`, `self.quizzes`: `list`
- `is_correct()` 반환값: `bool`
- JSON으로 바꾼 퀴즈와 게임 기록: `dict`

### 4. 메뉴와 공통 입력 검증: 약 1분

열어 둘 코드: `quiz_game.py:35-88`, `quiz_game.py:126-167`

말할 내용:

> 메뉴는 사용자가 종료 시점을 정하므로 반복 횟수를 미리 알 수 없습니다.
> 그래서 `run()`에서 `while True`를 사용하고 5번을 선택하면 `break`로
> 끝냅니다. 메뉴 번호에 따라 `if/elif/else`로 서로 다른 메서드를 호출합니다.

> `input()`은 숫자를 입력해도 항상 문자열을 반환합니다. `read_number()`는
> 먼저 `strip()`으로 앞뒤 공백을 제거하고, 빈 입력인지 확인한 다음 `int()`로
> 변환합니다. `abc`처럼 변환할 수 없는 값은 `ValueError`를 `except`로 잡고,
> 숫자여도 허용 범위를 벗어나면 다시 입력받습니다. 이 메서드를 메뉴, 문제 수,
> 정답 번호, 삭제 번호에 재사용해 검증 규칙의 중복을 줄였습니다.

종료 처리까지 설명합니다.

> `Ctrl+C`는 `KeyboardInterrupt`를 잡아 현재 상태를 저장하고 종료합니다.
> 실제 터미널의 `Ctrl+D`는 다시 입력받고, 파이프나 파일 입력이 끝난 경우에는
> 무한 반복하지 않도록 상위로 전달한 뒤 저장하고 종료합니다.

### 5. 퀴즈 플레이 흐름: 약 1분 20초

열어 둘 코드: `quiz_game.py:168-230`

말할 내용:

> 먼저 퀴즈가 하나도 없는 예외 상황을 처리합니다. 퀴즈가 있으면 사용자가
> 풀 문제 수를 고르고 `random.sample()`로 원본 목록을 변경하지 않으면서
> 중복 없이 무작위 문제를 선택합니다. 선택된 문제의 개수는 이미 정해져
> 있으므로 여기서는 `for` 반복문이 적합합니다. `enumerate(start=1)`을 써서
> 문제 객체와 화면에 표시할 1번부터의 번호를 함께 얻습니다.

`Quiz.display()`와 `Quiz.is_correct()`를 함께 가리키며 말합니다.

> 게임 클래스가 문제 내부의 출력 형식과 정답 판정을 직접 구현하지 않고,
> 각 `Quiz` 객체의 `display()`와 `is_correct()`에 요청합니다. 이것이 객체에
> 데이터와 관련 동작을 함께 묶은 이유입니다.

점수 부분을 설명합니다.

> 기본 점수는 `맞힌 수 / 전체 수 * 100`을 반올림합니다. 힌트는 문제당 한
> 번만 사용할 수 있고 사용 횟수마다 5점을 빼며, `max(0, ...)`으로 음수가
> 되지 않게 합니다. 게임 결과는 날짜와 함께 딕셔너리로 만들어
> `score_history` 리스트에 추가하고, 최고 기록과 비교한 다음 즉시 저장합니다.

### 6. 추가·목록·삭제: 약 50초

열어 둘 코드: `quiz_game.py:232-295`

말할 내용:

> 퀴즈 추가에서는 문제, 선택지 네 개, 정답, 힌트를 입력받습니다. 선택지는
> 정확히 네 번 반복하므로 `for range()`를 사용합니다. 입력값으로 `Quiz`
> 객체를 만들고 `self.quizzes.append()`로 같은 목록에 추가한 뒤 저장합니다.
> 따라서 사용자가 추가한 문제도 기본 문제와 구분 없이 목록, 랜덤 출제,
> 힌트, 삭제 기능에 자동으로 연결됩니다.

> 목록은 `enumerate()`로 표시하고, 삭제할 때 화면 번호는 1부터 시작하지만
> 리스트 인덱스는 0부터 시작하므로 `quiz_number - 1`을 사용합니다. 실수로
> 삭제하지 않도록 한 번 더 확인한 뒤 `del`로 제거하고 즉시 JSON에 반영합니다.

### 7. JSON 영속성과 오류 복구: 약 1분 10초

열어 둘 코드: `quiz.py:62-82`, `quiz_game.py:346-414`, `511-530`

말할 내용:

> 프로그램의 메모리는 종료하면 사라지기 때문에 추가한 문제와 점수를
> `state.json`에 저장합니다. JSON은 클래스 객체를 직접 저장할 수 없으므로
> `Quiz.to_dict()`로 단순한 딕셔너리로 바꾸고, 불러올 때는
> `Quiz.from_dict()`로 다시 객체를 만듭니다.

> 저장할 때 `encoding="utf-8"`과 `ensure_ascii=False`를 사용해 한글을 그대로
> 보존합니다. 바로 원본 파일에 쓰지 않고 `state.json.tmp`에 먼저 쓴 다음
> 교체해서 저장 도중 중단되어 원본이 깨질 가능성을 줄였습니다.

> 파일이 없으면 기본 퀴즈로 새 파일을 만들고, JSON 문법이나 내부 스키마가
> 손상되면 `try/except`에서 오류를 안내한 뒤 기본 7개로 복구합니다. 단순히
> JSON 문법만 확인하는 것이 아니라 퀴즈와 점수의 자료형 및 범위까지 검사합니다.

## 2분 실행 시연 순서

발표 전에 터미널 폭을 충분히 넓히고 프로젝트 루트에서 시작합니다.

```bash
python3 main.py
```

다음 순서로 입력하면 필수 기능과 보너스를 짧게 함께 보여 줄 수 있습니다.

1. 메뉴에서 `abc`, `9`, 빈 입력을 차례로 입력해 검증 메시지를 보여 줍니다.
2. `3`을 선택해 기본 문제와 사용자가 추가한 문제가 같은 목록에 나오는 것을
   보여 주고, 삭제 질문에는 `n`을 입력합니다.
3. `1`을 선택하고 문제 수는 `1`을 입력합니다.
4. 답 대신 `H`를 먼저 입력해 힌트와 5점 차감 안내를 보여 줍니다.
5. `1~4` 중 하나를 입력해 결과와 기록 저장을 보여 줍니다.
6. 메뉴에서 `4`를 선택해 최고 점수와 날짜가 포함된 전체 기록을 보여 줍니다.
7. `5`로 종료하고 다시 실행해 기록이 유지되는 것을 보여 줍니다.

무작위로 나온 문제의 정답을 몰라도 시연 목적에는 문제가 없습니다. 핵심은
정답을 맞히는 것이 아니라 입력 → 판정 → 점수 → 저장 흐름을 보여 주는 것입니다.

## 예상 질문과 짧은 답변

### 왜 클래스를 두 개로 나눴나요?

`Quiz`는 문제 한 개의 데이터와 판정을, `QuizGame`은 여러 문제와 전체 진행 및
저장을 담당하게 해 책임을 분리했습니다. 수정과 테스트 범위도 명확해집니다.

### `self`는 무엇인가요?

현재 메서드를 실행 중인 객체 자신입니다. `self.quizzes`라고 쓰면 각
`QuizGame` 객체가 가진 퀴즈 목록에 접근합니다.

### `while`과 `for`를 어떻게 구분했나요?

메뉴나 재입력은 언제 끝날지 몰라 `while`을, 선택지 네 개나 선택된 퀴즈처럼
반복 대상과 횟수가 정해진 경우에는 `for`를 사용했습니다.

### 왜 `answer - 1`을 사용하나요?

사용자에게 보여 주는 번호는 1~4이지만 Python 리스트 인덱스는 0~3이기
때문입니다.

### 왜 객체를 JSON에 바로 저장하지 않나요?

기본 `json` 모듈은 사용자 정의 `Quiz` 객체를 직접 변환하지 못합니다.
그래서 `to_dict()`로 JSON이 표현할 수 있는 `dict`와 `list`로 바꿉니다.

### 파일이 손상되면 어떻게 되나요?

JSON 읽기와 내부 데이터 검증에서 발생하는 오류를 잡고 퀴즈 7개, 점수 없음,
빈 기록 목록으로 초기화한 뒤 정상적인 `state.json`을 다시 저장합니다.

### 추가한 퀴즈에도 힌트와 다른 기능이 연결되나요?

네. 추가할 때 힌트를 필수로 받고 완성된 `Quiz` 객체를 공통
`self.quizzes` 리스트에 넣기 때문에 목록, 플레이, 힌트, 삭제, 저장에 모두
같이 연결됩니다. 예전 JSON처럼 힌트가 없으면 자동 힌트를 생성합니다.

### 기본 문제는 7개인데 왜 화면에는 8개인가요?

`default_quizzes.py`의 기본 문제는 7개이고, 실행 실습 중 직접 추가한 문제
1개가 `state.json`에 저장되어 현재는 8개입니다. 이것이 데이터 영속성이
동작한다는 증거입니다.

### `random.sample()`을 사용한 이유는 무엇인가요?

선택한 문제 수만큼 중복 없이 뽑을 수 있고 원본 퀴즈 목록의 순서를 바꾸지
않기 때문입니다.

### 최고 점수가 같으면 어떤 기록을 남기나요?

`(점수, 정답 수, 전체 문제 수)` 튜플을 비교해 같은 점수라면 더 많은 문제를
맞힌 기록을 우선합니다. 같은 기록을 반복한 경우에는 불필요하게 최고 기록을
갱신하지 않지만 전체 게임 히스토리에는 모두 남습니다.

### 왜 임시 파일에 먼저 저장하나요?

원본에 쓰는 도중 프로그램이 중단되면 기존 파일까지 깨질 수 있습니다.
임시 파일 쓰기가 끝난 뒤 원본과 교체하면 그 위험을 줄일 수 있습니다.

### 테스트는 무엇을 검증하나요?

26개 테스트가 객체 검증, 잘못된 입력, `Ctrl+C`와 `Ctrl+D`, 랜덤 출제,
힌트 감점, 추가·삭제·재로드, 최고 점수, 전체 기록, 손상 JSON 복구와 저장
실패를 검사합니다.

### Git에서 `add`, `commit`, `push`의 차이는 무엇인가요?

`add`는 다음 기록에 넣을 변경을 선택하고, `commit`은 선택한 변경을 로컬
이력으로 저장하며, `push`는 그 커밋을 GitHub에 전송합니다.

### 메모리 릭 이슈는 무엇이었나요?

현재 프로그램의 메모리 릭이 아니라, 수정 전 자동 테스트가 허용되지 않는
입력 `2`를 대기 없이 계속 반환하면서 재입력 안내를 메모리에 쌓은
테스트 입력 설정 문제였습니다. 현재는 입력 순서를 올바르게 수정했고,
26개 테스트를 같은 프로세스에서 100회 반복해도 메모리가 안정적이었습니다.

## 설명할 때 틀리기 쉬운 표현

- “기본 퀴즈가 8개다”가 아니라 “기본 7개 + 저장된 사용자 문제 1개”입니다.
- `Ctrl+D`를 모든 환경에서 막는 것이 아닙니다. 실제 대화형 터미널에서는
  다시 묻고, 파이프 입력의 끝에서는 안전하게 저장 후 종료합니다.
- JSON은 데이터베이스가 아니라 이 과제에서 사용하는 UTF-8 텍스트 저장
  형식입니다.
- 점수는 단순 정답 개수가 아니라 100점 기준 비율에서 힌트 감점을 뺀 값입니다.
- `readline`은 한글 지우기를 직접 구현한 코드가 아니라 터미널 줄 편집을
  활성화하는 Python 표준 모듈입니다.
- “예외를 무시했다”가 아니라 “예상 가능한 예외에 복구 동작을 정의했다”고
  설명합니다.
